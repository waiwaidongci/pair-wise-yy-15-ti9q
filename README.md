# hxyfront-62014 赛鸽训放记录

源提示词编号：9

面向赛鸽棚的训放记录前端工具：按**训放批次**登记放飞信息，按**足环号**登记归巢，自动处理跨夜用时、重复报时、待核与未归巢名单，成绩更正后排行、总览、血统档案全部重算。

## 业务规则（在 `src/domain/` 中实现，纯函数）

- **训放批次**：每批登记放飞日期、放飞时刻、地点、距离（公里）、天气和放飞足环名单。
- **归巢登记**：按足环号分别登记归巢日期、归巢时刻与健康状态（正常 / 受伤 / 生病 / 疲惫）。
- **跨夜用时**：归巢日期与时刻独立登记，用时按真实时间戳计算。次日凌晨归巢不会被判成“早于放飞”；若归巢时间戳真的早于放飞，记为时间矛盾，只进待核。
- **有效成绩与排行**：批次距离已登记、天气已填、健康为“正常”、且时间不矛盾的记录才进排行；按用时升序（先到在前）计算名次与分速（米/分）。
- **只进待核、不占排行**：缺距离、缺天气、健康异常（含未登记健康）或时间矛盾的记录进入待核队列并列出原因；补齐信息（待核页可直接补录批次距离/天气，成绩行可「更正」健康与时间）后自动进入排行。
- **同羽同批只留一条**：重复报时一律沿用先到记录，新报时不覆盖；若新报时反而更早，提示去「更正」原记录而非悄悄替换。
- **未归巢名单**：放飞名单中尚无任何归巢记录的足环自动进入名单；在未归巢页或批次页补录归巢后自动移出；删除归巢记录会重新进入名单。
- **联动重算**：任何批次或成绩更正后，排行、鸽棚总览、单羽档案与按血统统计的历史成绩均由规则层重新推导，页面不缓存派生数据。

## 三层结构

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 规则 | `src/domain/` | 类型模型（`types.ts`）与全部业务规则 / 派生计算（`rules.ts`），不依赖 React 与存储 |
| 存档 | `src/store/` | localStorage 持久化、内置示例数据、启动规范化（脏数据按先到去重）、`LoftContext` 状态操作 |
| 页面 | `src/pages/`、`src/components/` | 鸽棚总览、训放批次、成绩排行、未归巢、待核、鸽棚档案/血统六个页面 |

页面包括：鸽棚总览（归巢率/平均分速/未归巢/待核）、训放批次（批次登记、归巢报时、排行与待核）、成绩排行（按批次+血统筛选）、未归巢提醒（行内补录）、待核队列（缺距离/天气就地补录）、单羽赛鸽档案（含配对记录）与按血统筛选的历史成绩。

数据保存在浏览器 localStorage（键 `hxyfront-62014-loft-v1`），顶栏「重置示例」可恢复内置演示数据（含跨夜归巢、重复报时、受伤、缺距离、未归巢等场景）。
